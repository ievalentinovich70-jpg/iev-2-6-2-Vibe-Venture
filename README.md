# Vibe Venture — MVP-лендинг

Vibe Venture — небольшая венчурная фирма для ИИ-стартапов на ранней стадии. Фирма ищет команды с понятной проблемой, прототипом или MVP и может предоставить:

- **микрогрант** — небольшую финансовую поддержку на раннем этапе;
- **продуктовую обратную связь** — разбор продукта и гипотез;
- **помощь с упаковкой питча** — подготовку презентации для инвесторов;
- **первые пилотные интро** — знакомство с потенциальными пилотными клиентами.

Целевая аудитория сайта — основатели ИИ-стартапов. Они должны понять предложение фирмы, открыть подробное описание компании и оставить заявку на первичный отбор.

Этот репозиторий — локально воспроизводимый MVP-лендинг: два экрана, одна форма заявки, клиентская и серверная валидация, хранение заявок в SQLite и выгрузка их в CSV локальным Node.js-скриптом.

## Возможности

- **Два экрана**: основной лендинг и экран подробного описания компании (`/about`).
- **Форма заявки на первичный отбор** с клиентской валидацией (мгновенные ошибки в UI) и серверной валидацией через Zod (повторная проверка на API).
- **Сохранение заявок в SQLite** — база создаётся автоматически при первом запуске.
- **CSV-выгрузка** — Node.js-скрипт читает заявки из SQLite и записывает их в CSV-файл.
- **Понятный результат отправки** — после успешной отправки пользователь видит подтверждение.

## CSV-выгрузка заявок

Скрипт [`scripts/export-csv.ts`](scripts/export-csv.ts) читает все сохранённые заявки из SQLite и записывает их в файл [`exports/applications.csv`](exports/applications.csv) (перезаписывая предыдущую выгрузку). Файл записывается в кодировке UTF-8 с BOM, чтобы корректно открывался в Excel на Windows.

### macOS / Linux

```bash
npm run export:csv
```

Результат: файл `exports/applications.csv` в корне проекта.

### Windows (cmd или PowerShell)

```powershell
npm run export:csv
```

Результат: файл `exports\applications.csv` в корне проекта.

> **Примечание для Windows**: если CSV открывается в Excel с «кракозябрами» — откройте его через меню «Данные → Из текста/CSV» и выберите кодировку UTF-8. Файл уже содержит BOM, поэтому в большинстве случаев Excel определит кодировку сам.

## Форма заявки и валидация

Поля формы:

| Поле | Тип | Правила (Zod) |
| --- | --- | --- |
| Имя основателя | текст | 2–100 символов |
| Email | email | валидный email-адрес |
| Название стартапа | текст | 2–100 символов |
| Проблема | текст | 20–2000 символов |
| Стадия | выбор | `idea` / `prototype` / `mvp` |
| Питч | текст | 20–2000 символов |

Валидация выполняется в два слоя:

1. **Клиентская** — Zod-схема из [`lib/validation.ts`](lib/validation.ts) проверяет данные в браузере до отправки; ошибки показываются под полями.
2. **Серверная** — тот же Zod-схема проверяет данные в API-роуте [`app/api/applications/route.ts`](app/api/applications/route.ts). При невалидных данных API возвращает `400` со списком ошибок; при успехе — `201` с данными заявки.

## База данных

SQLite-файл `data/applications.db` создаётся автоматически при первом запуске. Таблица заявок:

```sql
CREATE TABLE IF NOT EXISTS applications (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  founder_name TEXT NOT NULL,
  email        TEXT NOT NULL,
  company_name TEXT NOT NULL,
  problem      TEXT NOT NULL,
  stage        TEXT NOT NULL,
  pitch        TEXT NOT NULL,
  created_at   TEXT NOT NULL DEFAULT (datetime('now'))
);
```

## API

### `POST /api/applications`

Принимает JSON с полями формы (см. таблицу выше).

- `201 Created` — заявка сохранена, в ответе данные заявки.
- `400 Bad Request` — данные не прошли Zod-валидацию, в ответе `{ errors: [...] }`.
- `405 Method Not Allowed` — запрос не POST.

## Сценарий проверки (для ревьюера)

1. **Установка**: `npm install`.
2. **Запуск**: `npm run dev`, открыть <http://localhost:3000>.
3. **Основной экран**: убедиться, что лендинг объясняет, кому помогает Vibe Venture и какую ценность предлагает (микрогрант, продуктовая обратная связь, упаковка питча, пилотные интро).
4. **Второй экран**: перейти из секции «О нас» на `/about` с подробным описанием компании и вернуться на основной экран.
5. **Клиентская валидация**: отправить форму с пустыми/некорректными полями — увидеть ошибки под полями без обращения к серверу.
6. **Серверная валидация**: отправить валидную форму — получить понятное подтверждение об успешной отправке.
7. **Хранение**: убедиться, что заявка появилась в `data/applications.db` (например, через `npm run export:csv` или SQLite-клиент).
8. **CSV-выгрузка**: выполнить `npm run export:csv` и открыть `exports/applications.csv` — в файле должны быть все отправленные заявки.
9. **Повторная выгрузка**: отправить ещё одну заявку, снова запустить выгрузку — CSV обновится.
